## 2. Пускане на промени

От папката `D:\ВМГ\napbg`:

```
npm run build        # проверка, че всичко се компилира
vercel.cmd deploy --prod --yes
```

В PowerShell ползвайте `npm.cmd`, `npx.cmd`, `vercel.cmd`, защото скриптовете са забранени на компютъра.
Влизането във Vercel е направено. Ако изтече: `vercel.cmd login`.

## 3. Свързване на домейн (утре)

1. Vercel → проект `kasabg` → Settings → Domains → Add. Въведете домейна.
2. При доставчика на домейна въведете DNS записите, които Vercel показва (обикновено A запис за основния домейн и CNAME за `www`).
3. Изчакайте да стане „Valid Configuration“ (минути до часове).
4. **Направете сайта публичен:** Settings → Deployment Protection → изключете Vercel Authentication за production.
5. **Supabase → Authentication → URL Configuration:** задайте Site URL на новия адрес и го добавете в Redirect URLs. Иначе имейлите за потвърждение сочат към стария адрес.
6. Заменете `[наименование на дружеството]`, `[ЕИК]`, `[адрес]`, `[имейл]` в страниците `terms` и `privacy` и ги дайте на юрист.

## 4. Gmail за n8n

1. Отворете процеса „изпращане на електронна бележка“.
2. Кликнете възела „Изпрати по Gmail“ → създайте нов Credential → „Sign in with Google“.
3. Направете същото в процеса „месечно напомняне“.
4. Включете (Publish) процеса. Докато е изключен, бележките остават `pending`.
5. Тест: в таблото добавете „Тестова поръчка“ с ваш имейл и проверете пощата.

Лимит на Gmail: около 500 имейла на ден. За повече е нужен друг доставчик (Resend, SMTP на домейна).

## 5. Тайните ключове

- **Таен ключ за n8n ↔ база:** записан е в таблицата `private.settings` (Supabase), във Vercel (променлива `N8N_SECRET`) и в n8n процесите „бележка“ и „напомняне“. За смяна: обновете го на всички места.
- **Публичен (publishable) ключ на Supabase:** безопасен е в сайта. Не слагайте **service_role** ключ никъде в сайта.
- **API ключ на магазин:** виждат го само собственикът. При изтичане се сменя от таблицата `stores`.

## 6. Какво още трябва да се направи (по приоритет)

1. Gmail свързване и тест на бележките.
2. Валидиране на XML файла в системата на НАП. Структурата е от публична имплементация (escapeboy/nra-audit-generator), не от официална XSD.
3. Юрист за общите условия и поверителността.
4. Supabase → Authentication → включете „Leaked password protection“, ако планът позволява.
5. Реални цени на плановете (сега са примерни) и плащане, ако искате.
6. Shopify конектор, английска версия.

## 7. Резервни копия и поддръжка

- Supabase прави автоматични копия според плана. Проверете в Dashboard → Database → Backups.
- Проверявайте предупрежденията: Supabase → Advisors. Предупрежденията за `SECURITY DEFINER` функциите са очаквани (`ingest_order`, `mark_receipt_sent`, `monthly_digest`, `get_api_key`): всички проверяват ключ или собственик.
- Free планът на Supabase спира проекта при дълго неактивност. За реална работа вземете платен план.

## 9. Вход, роли и админ панел

- **Регистрация** с избор „Имам магазин“ / „Счетоводител съм“. Изборът се пази в профила (`user_metadata.role`) и определя какво вижда потребителят в таблото.
- **Забравена парола:** `/forgot` → писмо → `/auth/callback` → `/reset`.
- **Админ панел:** `/admin`. Достъп имат само имейлите в таблицата `private.platform_admins` (сега: vpmfinance01@gmail.com). Трябва да сте регистрирани и потвърдени с този имейл. Нов админ:
  `insert into private.platform_admins values ('имейл@домейн');`
- В панела: всички магазини, брой поръчки, бележки, статус на файла за миналия месец, запитвания от формата „Контакти“, удължаване на пробния период (+14 дни) и смяна на плана.

### Настройки в Supabase (Authentication), които трябва да направите ръчно
1. **URL Configuration:** Site URL = адресът на сайта; в Redirect URLs добавете `https://ВАШИЯТ-ДОМЕЙН/auth/callback` (и `http://localhost:3100/auth/callback` за тест). Без това линковете за потвърждение и за нова парола няма да работят.
2. **Email templates:** сменете текстовете на английски (Confirm signup, Reset password) на български.
3. **SMTP:** вграденият имейл на Supabase е ограничен до малко писма на час. За реална работа добавете собствен SMTP (Authentication → SMTP Settings), например Resend или Gmail.
4. **Вход с Google (по желание):** Authentication → Providers → Google; въведете Client ID и Secret от Google Cloud Console, като Authorized redirect URI е показаният в Supabase. След това във Vercel добавете променлива `NEXT_PUBLIC_GOOGLE_LOGIN=1` и качете отново сайта. Докато променливата я няма, бутонът „Продължи с Google“ е скрит.
